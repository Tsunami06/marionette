## 后续顺序

| 阶段 | 工作 | 验收 |
|---|---|---|
| 1：设备和数据验收 | 固定设备、截图分辨率、布局；核对候选数据 | 对照截图正确识别金币、等级、回合、商店；成功完成一次购买 |
| 2：库存识别 | 棋盘、备战席、星级、装备；跨帧跟踪购买与合成 | 知道每个棋子的位置；识别满备战席、合成、替换 |
| 3：基本动作闭环 | 上下场、换位、出售、刷新、经验、装备 | 前置条件通过后执行；结果有独立证据；不确定时暂停 |
| 4：界面状态机 | 准备、战斗、选秀、强化、装备选择、特殊奖励、结算 | 正常界面可转换，弹窗后不会误操作底层棋盘 |
| 5：固定阵容规则 | 过渡、目标牌、站位、装备、升级与搜牌预算 | 准备阶段按预算和剩余时间完成计划 |
| 6：整局验收 | 从接管至结算；错误恢复与人工暂停 | 记录连续10局完成率、介入原因、误操作和各环节耗时 |
| 7：陪玩观察与互动 | 切换至老板棋盘、返回确认、局势事件、语音互动 | 操作能力支撑及时观察与回应 |

当前购买确认只包含金币扣除与目标名称消失，不是库存独立确认。旧 Sunflower 的棋盘读取和动作接口可复用，但尚未接入新会话并完成当前布局验证。

## 第一轮实机步骤（Windows）

1. 准备 Python 3.11、已开启 ADB 的设备或模拟器；确认真实 ADB 地址和端口。
2. 安装 `pip install -e ".[transport]"`，复制 `config/example.toml` 为 `config/local.toml`，填入地址端口。
3. 手动进入对局，运行 `doctor --capture-only` 和 `probe`，保存输出与原始 PNG。
4. 用 `calibrate --image <PNG> --output runs/calibration.html` 框选；导出布局并同步配置尺寸。
5. 安装 `pip install -e ".[device]"`，运行 `observe`；对照截图核对字段，必要时用 `replay` 调整。
6. 数据与布局核验后才开启本地执行开关；预览一次 `buy --slot N`，再执行一次并检查前后截图和库存。

暂停、失败和耗时均写入日志。第一轮结果决定后续识别方法和性能优化；不预设端到端延迟。
